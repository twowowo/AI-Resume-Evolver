一、 后端核心概念（分布式、高并发、安全）[50条]
幂等性 (Idempotency)：通过 Token 机制与数据库唯一索引确保分布式接口重试下的数据一致性。

分布式锁 (Distributed Lock)：基于 Redis (Redlock) 或 Zookeeper 实现跨节点的互斥资源访问控制。

熔断降级 (Circuit Breaker)：利用 Sentinel 或 Hystrix 在服务过载时自动切断非核心链路，保障系统可用性。

背压机制 (Backpressure)：在系统过载时向上游反馈压力，防止请求堆积导致服务雪崩。

读写分离 (Read-Write Splitting)：通过主从架构将写操作与读查询分发，提升大型数据库的吞吐能力。

分库分表 (Sharding)：利用水平拆分解决单表数据量过大导致的 B+ 树索引过深与查询瓶颈。

缓存穿透 (Cache Penetration)：针对不存在的 Key 采用布隆过滤器（Bloom Filter）拦截非法请求。

缓存雪崩 (Cache Avalanche)：通过给缓存设置随机过期时间，防止大量 Key 同时失效冲击数据库。

消息最终一致性 (Eventual Consistency)：通过消息队列 (MQ) 的事务消息实现分布式系统的最终一致。

数据库事务 (ACID)：严格遵守原子性、一致性、隔离性、持久性，保障金融级业务数据安全。

慢查询分析 (Slow Query Analysis)：利用 EXPLAIN 命令分析执行计划，优化索引覆盖与扫描行数。

服务发现 (Service Discovery)：基于 Nacos 或 Consul 实现微服务动态扩容下的请求自动寻址。

热点 Key 治理：利用二级缓存或多级缓存策略解决 Redis 单个分片的流量瞬时集中问题。

死锁诊断 (Deadlock Diagnosis)：通过检测事务等待链，定位并消除高并发下的数据库资源竞争。

OAuth2.0 授权框架：工业级标准身份认证协议，通过 Access Token 实现资源的安全委托访问。

负载均衡 (Load Balancing)：应用一致性哈希算法在集群间均匀分配请求压力。

流量削峰 (Traffic Shaving)：利用消息中间件异步处理高峰期请求，平滑系统负载曲线。

数据脱敏 (Data Masking)：对手机号、身份证等敏感字段进行掩码处理，满足合规性审计要求。

限流算法 (Rate Limiting)：采用令牌桶（Token Bucket）或漏桶（Leaky Bucket）实现精准 QPS 控制。

分布式事务 (2PC/TCC)：解决跨微服务调用的原子性问题，适用于支付等高敏感业务。

JWT 验证 (JSON Web Token)：一种无状态的授权令牌方案，通过服务端签名校验用户信息，减少数据库查询压力。

API 网关认证 (API Gateway Auth)：在微服务入口统一处理鉴权、限流与黑白名单逻辑。

连接池调优 (Connection Pooling)：通过优化数据库连接池的最小/最大空闲参数，降低连接创建开销。

SQL 注入防御 (SQLi Defense)：强制使用预编译语句（Prepared Statements）将代码与数据分离，阻断恶意注入。

分段锁技术 (Segmented Locking)：类似于 ConcurrentHashMap 的思想，通过减小锁粒度提升多线程并发写能力。

优雅停机 (Graceful Shutdown)：在服务关闭前拒绝新请求并处理完存量任务，确保业务不中断。

多版本并发控制 (MVCC)：通过维护数据的多个快照版本，实现数据库的高效读写并发。

数据异构 (Data Heterogeneity)：将数据库数据同步至 ES 或 Redis，支持复杂的业务查询需求。

心跳检测 (Heartbeat)：节点间定期交换存活信号，实现集群成员状态的实时监控与自动剔除。

二进制日志 (Binlog)：记录数据库所有更改操作的日志，用于主从复制与数据归档。

双机热备 (Active-Standby)：核心节点采用一主一备架构，主机故障时实现秒级切备。

CAP 定理：在一致性、可用性、分区容错性中根据业务场景进行的权衡取舍。

WAL 技术 (Write-Ahead Logging)：所有修改操作先写日志再写磁盘，保证数据在崩溃后的持久化。

连接多路复用 (Multiplexing)：通过单一 TCP 连接并发处理多个逻辑流，提升网络通信效率。

零拷贝 (Zero-copy)：利用 mmap 或 sendfile 技术减少内核态与用户态间的数据拷贝次数。

防重放攻击 (Anti-Replay)：利用 Nonce 或时间戳校验，防止合法的请求包被黑客拦截并二次发送。

跨域资源共享 (CORS)：通过服务端配置允许受信任的域名跨域访问受保护的资源。

强制索引 (Force Index)：在复杂 SQL 查询中手动指定最优索引，纠正优化器的误判。

全表扫描监控：针对未走索引的查询进行告警，防止单条 SQL 拖慢整个数据库集群。

冷热数据分离：将历史低频数据迁移至廉价存储，核心业务只保留高性能的热数据。

乐观锁 (Optimistic Locking)：基于版本号机制实现，适用于读多写少的并发场景。

悲观锁 (Pessimistic Locking)：利用数据库排他锁，适用于写竞争极其激烈的业务场景。

跨机房容灾 (Geo-Redundancy)：在不同城市部署副本，应对物理区域级的突发灾害。

灰度发布 (Canary)：通过路由规则将特定比例的流量引导至新版本进行线上验证。

影子库压测：使用全链路压测产生的仿真数据写入影子库，避免污染生产环境。

请求合并 (Request Collapsing)：将同一时刻发起的相同查询合并为一个，减轻底层依赖压力。

逻辑删除 (Soft Delete)：使用状态位标记记录已删除，方便数据回滚与审计分析。

强一致性读：在分布式场景下通过路由到主库或同步等待，确保读到最新数据。

自增 ID 治理：防止自增 ID 耗尽，或在分库分表下引入分布式唯一 ID（如雪花算法）。

服务权重调度：根据节点配置差异动态调整负载均衡权重，实现资源最优分配。

二、 数据科学（清洗、模型、评估指标）[50条]
向量化操作 (Vectorization)：利用 Pandas 避免 Python 原生 for 循环，将计算效率提升数十倍。

异常值检测 (Outlier Detection)：应用 Z-Score 或 IQR (四分位距) 方法识别并清洗数据噪点。

特征工程 (Feature Engineering)：通过 One-Hot 编码、特征交叉与标准化提升模型对原始数据的捕捉力。

归因分析 (Attribution Analysis)：利用多维拆解定位业务指标波动的核心技术或产品因素。

北极星指标 (North Star Metric)：衡量产品核心价值增长的最关键单点指标。

A/B Testing：通过科学的流量分桶与假设检验（T-Test）验证新策略的显著性提升。

特征缩放 (StandardScaler)：将不同量级的特征映射到统一分布，加速模型收敛速度。

维度削减 (PCA)：利用主成分分析保留核心信息，同时降低高维数据计算复杂度。

交叉验证 (Cross-Validation)：通过 K-Fold 方法防止模型在特定数据集上产生过拟合。

精确率与召回率 (Precision vs Recall)：衡量分类模型在“搜得准”与“搜得全”之间的平衡关系。

AUC-ROC 曲线：用于评估分类器在不同阈值设定下的综合性能表现。

混淆矩阵 (Confusion Matrix)：直观展现模型在各类别上的分类错误分布情况。

数据偏斜处理 (Data Skew)：针对正负样本不平衡场景，采用 SMOTE 过采样或加权损失函数。

决策树调优 (Pruning)：通过预剪枝或后剪枝控制模型复杂度，提升泛化能力。

相关性热力图：展示多变量间的线性相关性，辅助特征筛选。

SHAP 值分析：基于博弈论解释黑盒模型中各特征对最终预测结果的贡献度。

指标平滑 (Exponential Smoothing)：处理时序数据噪声，提取核心业务趋势趋势。

多维数据立方体 (OLAP)：支持对海量业务数据进行多视角、下钻式的快速聚合分析。

样本量计算 (Power Analysis)：实验前根据预期提升与显著性水平确定所需的最小样本量。

长尾分布优化：针对占比极少但影响巨大的长尾数据进行的专项模型调优。

聚类分析 (Clustering)：利用 K-Means 或 DBSCAN 实现无监督的用户分群与模式发现。

梯度下降 (Gradient Descent)：通过计算损失函数梯度动态更新权重，寻找模型最优解。

欠拟合 (Underfitting)：模型过于简单，无法捕捉训练数据中的内在规律，导致精度低下。

L1/L2 正则化：通过在损失函数中增加惩罚项，抑制权重过大，有效防止模型过拟合。

归一化 (Min-Max Scaling)：将特征取值线性映射到 [0, 1] 区间，统一特征量纲。

特征重要性评分：基于 Random Forest 或 XGBoost 评估各变量对预测目标的贡献程度。

时序预测 (Time Series)：利用 ARIMA 或 Prophet 模型分析历史周期规律，预测业务趋势。

置信区间 (Confidence Interval)：给出参数估计的取值范围，反映统计结果的可靠程度。

P-value 显著性检测：在 A/B 实验中判断结果差异是由偶然性引起还是由策略变更引起。

深度学习 (Deep Learning)：利用多层神经网络提取非结构化数据（如图形、语音）的高阶特征。

反向传播 (Backpropagation)：将误差从输出层反向传递至输入层，优化网络各层权重的算法。

推荐算法 (Collaborative Filtering)：基于用户行为相似度或物品属性实现个性化精准分发。

点击率预测 (CTR Prediction)：估计用户点击特定内容的概率，常用于搜索与广告排序。

协同归因模型 (MTA)：在多触点营销环境中，科学分配各渠道对最终转化的贡献权重。

数据湖 (Data Lake)：支持海量原始格式数据的低成本存储，供后续数据挖掘与离线分析。

实时流处理 (Stream Processing)：利用 Flink 对业务埋点数据进行毫秒级窗口计算与实时指标产出。

独热编码 (One-Hot)：将类别变量转化为稀疏的二值向量，以便机器学习模型处理。

集成学习 (Ensemble)：通过组合多个弱学习器（如梯度提升树）获得更强大的强学习器。

冷启动问题 (Cold Start)：处理新用户或新物品缺乏历史行为数据时的推荐策略。

知识图谱 (Knowledge Graph)：通过实体与关系建模，实现业务逻辑的深层联想与推理。

语义分割 (Segmentation)：在像素级别对图像进行分类，常用于自动驾驶中的路况识别。

激活函数 (ReLU/Sigmoid)：为神经网络引入非线性变换，使其具备拟合复杂函数的能力。

池化层 (Pooling)：降低特征图维度，减少参数量并提升模型对平移的鲁棒性。

数据补全 (Imputation)：利用均值、中位数或回归方法填补原始数据集中的缺失值。

迁移学习 (Transfer Learning)：利用预训练模型的特征提取能力，在小样本任务上实现快速微调。

数据偏见 (Data Bias)：由于样本采集不平衡导致的模型决策不公，需通过重采样修正。

多变量测试 (Multivariate)：同时改变多个实验变量，通过方差分析观察变量间的交互作用。

逻辑回归 (Logit)：经典的二分类模型，通过 Sigmoid 函数将线性结果映射为概率。

随机森林 (Random Forest)：通过构建多棵决策树并取众数，显著提升预测的稳定性。

深度强化学习 (DRL)：模型通过与环境交互并获取奖励，自主学习最优决策路径。

三、 云原生/DevOps（Docker, K8s, CI/CD）[40条]
容器化 (Containerization)：利用 Docker 封装应用及其运行环境，实现“一次构建，到处运行”。

编排调度 (Orchestration)：利用 Kubernetes 实现容器集群的自动部署、扩展与高可用管理。

基础设施即代码 (IaC)：利用 Terraform 或 Ansible 实现云资源的自动化供给与版本化管理。

蓝绿部署 (Blue-Green Deployment)：通过两套生产环境切换实现版本平滑更新与零停机回滚。

金丝雀发布 (Canary Release)：将新版本逐步灰度给小部分用户，验证稳定性后再全量上线。

CI/CD 流水线：自动化代码集成、测试与部署流程，显著缩短软件交付周期。

可观测性 (Observability)：通过 Metrics、Logging、Tracing 三位一体实现对复杂系统的监控。

全链路追踪 (Tracing)：基于 Jaeger 或 Zipkin 追踪请求在各微服务节点间的调用链路。

镜像瘦身 (Image Slimming)：采用多阶段构建（Multi-stage build）减小 Docker 镜像体积。

配置中心 (Config Center)：实现应用配置的动态注入与实时下发，无需重启服务。

探针检测 (Liveness/Readiness)：Kubernetes 监测服务存活状态并自动重启异常实例。

资源配额 (Resource Quota)：精细化限制容器 CPU 与内存开销，防止单个服务耗尽物理节点资源。

Sidecar 模式：通过独立容器处理服务治理逻辑，实现业务逻辑与治理逻辑解耦。

无服务器架构 (Serverless)：根据请求流量自动触发函数执行，按需付费且无需管理底层服务器。

Ingress 控制器：充当 Kubernetes 的外部流量入口，支持基于路径或域名的 7 层负载均衡。

StatefulSet：专门用于管理数据库等有状态应用的容器控制器，保证 Pod 标识与存储的持久性。

Helm Chart：Kubernetes 的软件包管理工具，通过模板化方式管理复杂的部署资源清单。

滚动更新 (Rolling Update)：逐步替换旧 Pod 为新 Pod，在保证集群始终有可用副本的前提下完成升级。

GitOps：以 Git 仓库为系统状态的唯一信源，通过声明式配置驱动自动化同步部署。

私有镜像仓库：如 Harbor，提供镜像存储、漏洞扫描及基于角色的权限访问控制。

网络策略 (Network Policy)：通过定义 Pod 间的入站与出站规则，实现微服务级别的安全隔离。

持久化卷 (Persistent Volume)：将存储生命周期与 Pod 解耦，确保数据不会随着容器重启而丢失。

自动化扩缩容 (HPA)：根据 CPU 利用率或自定义业务指标动态调整 Pod 副本数量。

控制平面 (Control Plane)：Kubernetes 的核心管理大脑，负责节点调度、API 处理及状态同步。

数据平面 (Data Plane)：实际承载业务容器的 worker 节点及其网络插件。

服务网格 (Service Mesh)：如 Istio，通过注入拦截流量实现细粒度的服务治理与加密通信。

日志采集代理 (Logging Agent)：如 Fluentd 或 Filebeat，负责在各节点抓取容器日志。

声明式 API：用户只需描述系统的期望状态（Desired State），由 K8s 自动调和当前状态。

零信任架构 (Zero Trust)：不再默认信任内网流量，对所有服务间通信强制进行身份验证与加密。

混沌工程 (Chaos Engineering)：通过在生产环境主动注入故障（如杀死进程），验证系统的容错能力。

集群联邦 (Federation)：管理分布在不同区域或云服务商的多个 K8s 集群，实现全球负载平衡。

资源极限 (Limits/Requests)：强制规定 Pod 的资源申请量与使用上限，确保集群稳定性。

静态代码扫描 (SAST)：在 CI 阶段利用 SonarQube 扫描代码漏洞、命名规范与技术债。

容器运行时 (Runtime)：如 containerd 或 CRI-O，负责底层镜像拉取与容器生命周期管理。

多租户隔离：通过 Namespace 将不同业务部门的资源进行逻辑划分，避免互相干扰。

镜像版本回滚：在发现线上异常时，通过一行命令将 Deployment 镜像快速回退至上一个稳定版本。

健康自愈 (Self-healing)：系统检测到节点或容器异常时，自动重新调度 Pod 以维持副本数。

基础设施编排：利用 CloudFormation 等工具实现计算、网络、存储资源的跨地域统一编排。

自动化压力测试：利用 JMeter 或 Locust 集成到流水线中，在部署前验证代码的并发支撑力。

单元测试覆盖率：通过流水线阈值强制要求单元测试覆盖率达到 80%，从源头保证代码质量。

四、 新兴领域（LLM, RAG, 向量数据库）[40条]
RAG (检索增强生成)：通过从外部私有库检索相关文档注入 LLM，解决大模型时效性与幻觉问题。

向量嵌入 (Embedding)：将非结构化文本转化为高维数值向量，捕捉文本间的深层语义关系。

混合检索 (Hybrid Search)：结合关键词检索 (BM25) 与语义检索，兼顾精确匹配与意图理解。

多路召回 (Multi-query)：利用 LLM 自动将用户提问扩写为多条变体，提升底层素材命中率。

重排序 (Rerank)：利用交叉编码器对初筛结果进行精准排序，将最相关的素材塞入上下文。

提示工程 (Prompt Engineering)：通过设计高质量指令（CoT/Few-shot）引导模型输出期望结果。

余弦相似度 (Cosine Similarity)：衡量向量空间中两个文本片段语义接近程度的核心数学指标。

幻觉抑制 (Hallucination Mitigation)：通过注入引用溯源与事实核查机制降低 AI 生成内容的编造率。

上下文压缩 (Context Compression)：在保持核心语义的前提下精简冗余素材，节省 Token 开销。

向量数据库 (Vector DB)：专为高维向量设计的存储系统，支持千万级数据的毫秒级近似最近邻搜索。

思维链推理 (Chain of Thought)：引导模型分步骤拆解复杂任务，显著提升逻辑推理准确性。

长文本窗口 (Window Size)：衡量模型一次性处理长文档的能力，直接影响大规模知识库分析质量。

微调 (Fine-tuning)：在特定领域数据集上对通用模型进行二次训练，提升特定任务表现。

自修复检索 (Self-RAG)：让模型自主评估检索素材质量，若不相关则重新发起检索。

智能体编排 (Agent Orchestration)：利用 LangChain 或 AutoGPT 框架，让 LLM 具备自主规划并调用工具的能力。

多模态模型 (Multimodal)：支持同时理解并生成文本、图像、音视频等多种形态数据的统一模型。

系统指令 (System Prompt)：为模型设定长期的角色定位与行为边界，控制输出的语调与风格。

模型剪枝 (Pruning)：移除模型中对预测结果影响极小的参数，减少推理时的算力损耗。

Token 量化 (Quantization)：将模型权重从 32 位浮点数压缩为 8 位或 4 位，实现低资源部署。

文档切片策略 (Chunking)：根据语义完整性（如段落、标题）将长文拆分为适合检索的小块。

交叉编码器 (Cross-Encoder)：同时处理查询词与文档段，捕捉细粒度的相关性信息（通常用于重排）。

知识沉淀 (Knowledge Distillation)：通过“教师”大模型指导“学生”小模型的学习，实现模型的小型化。

Prompt 注入防御：检测并拦截试图绕过安全策略的恶意用户输入，保障 AI 应用安全。

自递归召回：模型根据上一步生成内容自动调整下一次检索的关键词，实现深层信息挖掘。

向量量化 (IVFPQ)：通过聚类与残差量化技术，在保证召回率的前提下极速压缩向量索引。

Few-shot Learning：在 Prompt 中提供少量示例，让模型快速理解任务格式与输出风格。

语义解析 (NL2SQL)：将用户的自然语言提问自动转化为精准的数据库查询语句。

合成数据 (Synthetic Data)：利用 LLM 批量生成高质量的模拟数据，用于解决特定任务的样本匮乏问题。

意图识别 (Intent Recognition)：解析用户指令背后的核心意图（如查询、对比、总结），触发不同工作流。

上下文缓存 (Context Caching)：缓存长文本中的静态背景信息，大幅降低重复调用的首字延迟。

动态少样本 (Dynamic Few-shot)：根据当前用户问题，实时从库中检索最接近的示例作为 Prompt。

端侧部署 (Edge AI)：在手机、电脑等本地设备上直接运行轻量化 LLM，保障隐私与离线体验。

对话一致性维护：通过管理会话窗口内的历史 Token，确保多轮对话不偏离预设主题。

生成式评价 (LLM-as-a-Judge)：利用更强大的模型自动评估其他模型的生成结果质量。

多路召回融合 (RRF)：通过倒数排名融合算法，综合不同检索工具的结果，生成最优排序。

隐私敏感屏蔽：在数据入库前自动识别并遮掩 PII（个人身份信息），确保知识库合规。

参数高效微调 (LoRA)：仅训练极少量的新增参数，即可让大模型适配特定的垂类领域。

提示词自动优化：利用演化算法或模型自我纠错，自动寻找能触发最佳回答的 Prompt 模板。

检索分级 (Tiered Retrieval)：先从本地内存缓存检索，未命中再下钻到持久化向量库，优化延迟。

指令对齐 (Alignment)：通过 RLHF 确保模型输出符合人类的道德标准与事实准则。
